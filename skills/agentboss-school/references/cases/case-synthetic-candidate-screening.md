# 合成案例：招聘筛选 Agent 把“高效”变成不可解释拒绝

> **SYNTHETIC_SCENARIO / ILLUSTRATIVE**：本案例中的组织、岗位、人员、事件、数据和结果均为虚构，只用于教学。它不是客户案例、法律建议或成效证据。

## 业务背景

一家虚构的连锁服务企业收到大量门店运营岗位申请。招聘团队希望 Agent 快速总结经历并排序，最初需求写成“自动淘汰不合适候选人”。

## 原始工作方式

招聘专员按岗位最低条件初筛，业务经理面试，HR 对拒绝流程负责。历史岗位描述包含未经复核的偏好词，简历数据也存在格式和语言差异。

## Agent 工作设计

团队把任务改为“辅助整理证据”：Agent 从获准字段中提取与公开岗位条件相关的经历，标出缺失或冲突，不推断受保护特征，不访问社交媒体，不自动拒绝。真人招聘专员核对原文并作推进决定。

## 关键决策与取舍

离线样例中，一个候选人因简历格式导致任职日期未被正确提取，Agent 给出“经验不足”。如果系统直接拒绝，这个可纠正的数据错误会变成高影响决定。

团队选择降低自动化层级：结构化硬条件用确定性检查；Agent 只做摘要和缺口提示；拒绝决定由受训真人完成并保留依据；定期按输入格式和群体切片检查错误模式。是否可以使用特定字段必须另行经过适用法律和组织政策评估。

## 责任、权限与证据

岗位负责人定义真实工作要求，HR 流程所有者对筛选制度负责，招聘专员对单次决定负责。评测保留字段提取准确性、错误类型、人工推翻原因和申诉/纠错路径，不保存与目的无关的数据。

## 结果与限制

本案例没有候选人数量、效率提升或公平性结果。它只说明高影响、人际和受监管场景通常更适合 Agent 辅助，而不是把最终责任交给模型。

## 可迁移的教训

当输入质量差、决定影响个人机会、错误难以逆转且验收需要价值判断时，先缩小 Agent 角色。真人在环也必须有足够信息、时间、训练和纠错权。

## 适合接入的课程节点

- `role/delegation-fit`：选择辅助而非自动淘汰；
- `governance/authority-and-least-privilege`：缩小数据和动作；
- `team/pilot`：设计基线、切片评测、退出条件和员工训练。
