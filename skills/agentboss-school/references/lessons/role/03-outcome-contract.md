# 第三课：把任务写成结果合同

## 学习结果

学生能把模糊指令改写为包含结果、证据、范围、权限、暂停条件、责任人和截止时间的结果合同。

## 核心概念

结果合同不是法律合同，也不等同于 prompt。它是 Agent Boss 与执行 Agent 之间可操作、可验收、可追责的工作定义。

最小结构包含八项：

1. 业务目的；
2. 交付结果；
3. 验收证据；
4. 数据和来源范围；
5. 允许动作；
6. 必须暂停或升级的条件；
7. 负责人与执行者；
8. 截止时间和未完成状态。

## 决策框架

先写“什么业务决定会使用这个结果”，再倒推交付和证据；随后缩小数据与动作范围，列出必须暂停的异常，最后绑定真人责任和结果未知状态。合同写不清时，不进入更高自治。

## 讲授

“帮我做一份竞品分析”是请求，不是可管理的工作。它缺少结果格式、来源边界、评判标准和停止规则。把它写成结果合同后，Agent 才能在范围内自主，真人也能在正确节点介入。

可复用模板：

```text
业务目的：为什么做，支持哪个决策。
交付结果：具体文件、结构、数量、语言和截止时间。
验收证据：每个结论如何被核对；哪些测试或来源必须存在。
数据范围：只可使用哪些数据；明确禁止哪些数据。
允许动作：可以读、写、调用或生成什么。
暂停/升级：遇到哪些缺失、冲突、风险或外部动作必须停。
责任链：发起真人、负责真人、执行 Agent、必要审批人。
未完成状态：失败、超时或结果未知时如何报告，禁止怎样静默重试。
```

市场简报示例：

```text
业务目的：为周一市场会议提供三个可讨论变化，不直接对外发布。
交付结果：800–1200 字中文简报，含三条结论和来源表，周一 09:00 前完成。
验收证据：每条结论至少对应一个获准来源；数字注明日期和口径。
数据范围：只读演示市场数据集；不得使用客户或生产数据。
允许动作：读取获准数据、计算、起草文件。
暂停/升级：来源冲突、数据缺失或需要发布时暂停并通知市场负责人。
责任链：市场负责人发起并负责；研究 Agent 执行；发布另行精确审批。
未完成状态：截止前报告缺口和已完成部分；不得伪造来源或自动发布。
```

结果合同不是把每一步都写死。它定义“什么算完成”和“哪里不能越界”，把具体规划空间留给 Agent。写成几十页操作手册可能同样失败，因为 Agent 只会机械执行过时步骤，却不知道业务结果。

## 失败模式与边界

- 把步骤清单当成结果，完成动作却没有业务交付；
- 证据只写“Agent 自评正确”；
- 没有失败、超时或结果未知状态，导致静默重试；
- 结果合同是项目运行接口，不是替代采购、劳动、隐私或其他法律合同。

## 实操

导师先把学生上一课的任务（或市场简报）改写成八项合同草稿，然后请学生只修改最不准确的一项。避免一次让学生填写整张表造成面试感。

如果学生提供真实工作，只保留抽象描述，不把原始内容写入学习存档。

## 完成证据

- `developing`：能把模糊任务改成具体交付结果。
- `capable`：合同包含可核对证据、权限范围和暂停条件。
- `strong`：还能定义失败/结果未知状态，并避免静默重试造成副作用。
- 没有产出或判断：记录 `unknown`。

## 降级路径

没有真实任务或不能披露时，使用本课市场简报合同。只在学生同意时保存其产物路径，绝不把合同正文塞进学习状态。
