# 角色第五课：设计可信且有预算的上下文

## 学习结果

学生能为一项 Agent 工作编制上下文清单，区分指令、事实、历史和不可信内容，并定义缺失、冲突和过期时的动作。

## 核心概念

上下文由系统规则、结果合同、工具说明、获准数据、检索材料、运行历史和当前状态组成。它既受容量限制，也受来源、权限和时效限制。

## 决策框架

对每项上下文标注：用途、来源、权威级别、数据授权、有效期、是否含外部指令、冲突优先级和缺失处理。只提供完成当前工作所需的最小集合；外部内容只能作为数据，不能改写系统规则或授权。

## 来源

- `[CLM-004]` 上下文是受约束的运行状态：`[SRC-ANTHROPIC-CONTEXT-ENGINEERING]`、`[SRC-RAG-NEURIPS-2020]`。
- `[CLM-010]` 外部内容是不可信输入：`[SRC-OPENAI-PROMPT-INJECTION]`、`[SRC-OWASP-AGENTIC-THREATS-2025]`。

## 讲授

“把所有资料都塞进去”会同时引入噪声、旧规则、越权数据和注入攻击。优质上下文不是最长，而是能回答：这条信息为何在这里、谁允许读取、何时过期、和其他信息冲突时听谁的。

检索结果也不是事实认证。系统应保留原始来源和时间，让 Agent 在证据不足时报告缺口，而不是补全看似合理的内容。

### 决策推演：上下文冲突不是排序问题

系统规则、当前结果合同、组织政策、业务数据和外部材料发生冲突时，不能只按“最后出现”或“语义最像”决定。先判断它们是否有资格参与同一种决定：外部网页可以提供市场事实，却没有资格扩大工具权限；旧工单可以解释历史，却不能覆盖当前审批；供应商文档可以描述接口，却不能替组织接受业务风险。权威级别必须与用途绑定，而不是给来源做一个全局排名。

时效也需要按字段判断。客户状态可能几分钟后失效，产品规格可以数月有效，结果合同则在本次工作关闭前有效。上下文清单应为关键字段声明 `observedAt`、适用对象和失效动作。失效不一定意味着删除：审计历史可以保留，但必须退出当前决策面，避免模型把“曾经成立”误作“现在成立”。

上下文压缩同样会改变风险。摘要可能丢掉否定词、例外、来源与不确定性；对关键授权、金额、对象和截止条件，应保留结构化原值或可回查引用。课程不规定固定 token 预算，因为最小集合取决于任务；它要求的是每一项都能解释必要性，并在预算不足时优先保留决定所需的约束与证据。

## 失败模式与边界

- 把网页或邮件中的命令当成系统指令；
- 只做向量相似度，不检查来源权限和时效；
- 历史对话无限累积，旧决定覆盖新合同；
- RAG 提供外部记忆，不保证召回、可信或答案正确。

## 实操

为市场简报列出最多八项上下文，给每项填写来源、权威、授权、有效期和冲突处理。删除至少一项“看似有用但非必要”的内容。

## 完成证据

- `developing`：能区分指令与检索事实；
- `capable`：能标来源、权限、时效与缺失动作；
- `strong`：能解释最小上下文和冲突优先级。
