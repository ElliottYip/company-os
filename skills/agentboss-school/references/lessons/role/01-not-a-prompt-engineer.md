# 第一课：Agent Boss 不是提示词工程师

## 学习结果

学生能解释 Agent Boss 的三个核心动作——委派、监督、负责——并指出 Agent 能执行工作但不能承担组织与业务责任。

## 核心概念

1. **Agent 使用者**关注“怎样让模型输出得更好”；**Agent Boss**关注“这项工作应不应该交出去、权限到哪、何时介入、凭什么验收、谁对结果负责”。
2. 能力、授权、责任是三件不同的事：Agent 可能有能力执行；组织可以只授权其中一部分；最终责任仍绑定真人。
3. Agent Boss 不是每一步都亲自指挥。好的管理是在目标、边界、观察点和升级规则明确后，让执行者在范围内行动。

## 决策框架

遇到 Agent 工作时依次问：它有何能力、这次获准做什么、哪个动作需要真人决定、谁对业务结果负责、用什么证据验收。任何一项答不出，先补责任设计，不增加自治。

## 讲授

提示词工程关注一次交互，Agent Boss 管理一个有后果的工作闭环。两者差别可以用一个市场简报说明。

如果你只是要求“写一份很专业的市场简报”，你把质量、数据来源、发布时间和外部发布权全藏在一句自然语言里。输出可能很流畅，但没有人能回答：它用了哪些数据？能不能直接发？错了谁停？什么才算完成？

Agent Boss 会先作五个管理决定：

1. 这项工作是否适合委派给 Agent；
2. 要交付什么可检查结果；
3. Agent 可以读取和执行哪些动作；
4. 哪些节点必须暂停给真人；
5. 哪个真人对业务结果负责。

因此，Agent Boss 的基本式不是“更长的 prompt”，而是：

```text
可委派工作 = 可验收结果 + 有界权限 + 可见执行 + 升级规则 + 真人责任
```

很多人以为“Agent 越自主，真人越不需要参与”。实际恰好相反：自主范围越大，责任合同、观察证据和停止条件越重要。真人不必审批每个低风险步骤，但必须设计哪些动作可以自主、哪些必须被拦住。

再区分三层：

- **能力**：Agent 技术上会不会调用发布工具；
- **授权**：组织是否允许它在这项工作中调用；
- **责任**：发布造成错误后，哪个真人必须解释、处置并改进系统。

把这三层混在一起，是 Agent 管理中最常见也最危险的错误。

## 失败模式与边界

- 只优化 prompt，却没有结果、权限和停止条件；
- 把“系统记录了操作者”误当成真人承担了责任；
- 把每一步审批当治理，反而让真人疲劳点击；
- 本课定义是 AgentBoss 的操作口径，不替代行业法律责任判断。

## 实操

给学生这个短情境并先讲清示范答案，再邀请他选择：

> 一个内容 Agent 能读取演示市场数据、写简报，也能调用发布工具。负责人说：“以后市场简报都交给它。”

示范判断：它具备写作和发布**能力**；可以被授权读取指定数据并起草；正式发布属于高影响动作，应绑定准确内容和责任上下文等待真人审批；市场负责人仍对发布结果负责。

可选巩固：请学生用自己的话指出这段话中的“能力、授权、责任”各是什么。不要把回答当作继续课程的门槛。

## 完成证据

- `developing`：能说出 Agent 不能替真人承担最终责任。
- `capable`：能在情境中分别指出能力、授权和责任。
- `strong`：还能提出合适的暂停点或升级规则。
- 未观察到上述行为：记录 `unknown`。
