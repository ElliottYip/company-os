# 运营第二课：观察真正可行动的信号

## 学习结果

学生能设计一页 Agent 工作观测表，区分健康、过程、风险、成本和结果证据，并为异常信号绑定处置人。

## 核心概念

观测不是“保存全部对话”。至少区分：工作状态、trace/工具动作、权限与审批、成本/延迟、评测分数、最终环境状态和业务接受决定。

## 决策框架

每个信号必须回答：它支持哪个决定、正常范围是什么、谁响应、多久响应、包含哪些敏感数据、保留多久。没有处置动作的高噪声告警应删除或降级为诊断数据。

## 来源

- `[CLM-006]` trace 不等于结果：`[SRC-ANTHROPIC-AGENT-EVALS]`、`[SRC-TAU-BENCH-2024]`。
- `[CLM-023]` 监督还要支持适当依赖与接管态势感知：`[SRC-TRUST-AUTOMATION-2004]`。
- `[SRC-GOOGLE-SRE-MONITORING]` 支持可行动监控原则；`[SRC-OTEL-SEMCONV]` 提供跨工具语义参考。
- `[CLM-018]` `[SRC-LANGFUSE]`、`[SRC-PHOENIX]` 只是工具样本。

## 讲授

一次工具调用失败后自动恢复，可能是诊断事件，不必叫醒负责人；一次静默越权读取即使最终输出正确，也是治理事件。Agent 运营不能只看成功率，也不能只看 token。

日志本身会包含用户输入、检索文档、工具参数和结果，应按数据边界做脱敏、访问控制和留存。可观测性不能成为新的数据泄露面。

### 决策推演：先从要做的决定倒推信号

如果负责人要判断“是否暂停写操作”，需要的是写动作频率、拒绝率、未确认副作用和授权状态，而不是完整思维文本；如果要判断“质量是否回归”，需要冻结任务集、版本与 grader 结果，而不是挑几条漂亮对话；如果要判断“业务是否接受”，需要环境结果和责任人的验收记录。一个信号不能回答任何运行决定，就不应进入告警面。

阈值也不能脱离时间窗和基线。“失败率 5%”可能是五次调用中的一次，也可能是十万次中的五千次；平均延迟正常时，P99 仍可能让关键工作超时。运行卡应同时写分母、观察窗、分群和触发后的动作。对安全阻断项则不一定等待统计显著性，例如一次越权发送企图就可能触发暂停与调查。

trace 采样要服从风险。低风险成功流可以采样，高风险动作、审批变化、策略拒绝、结果未知和事故记录应按政策完整保留。保留完整不等于向所有人开放：敏感字段可做结构化摘要、哈希绑定或分权访问，同时让调查人员能证明记录未被事后改写。

可观测界面也会塑造依赖。只展示绿色成功率会诱导过度信任，只展示原始 trace 又会让负责人在异常时找不到状态。更合适的界面同时暴露能力边界、当前不确定性、最近控制动作和接管入口。`[CLM-023]` 支持的是“让依赖匹配能力与情境”这一原则，不是要求显示一个通用信任分数。

## 失败模式与边界

- 收集一切但没人负责响应；
- 用流畅输出掩盖工具失败或政策违规；
- 在 trace 中存 Secret、客户原文或不必要个人信息；
- 仪表盘指标漂亮却没有环境结果和抽样复核。

## 实操

设计最多十个信号的运行卡片。每项写明来源、阈值、责任人和动作；至少包含一个权限信号、一个结果信号和一个成本信号。

## 完成证据

- `developing`：能区分过程与结果；
- `capable`：信号有阈值、负责人和动作；
- `strong`：兼顾数据最小化与错误预算。
