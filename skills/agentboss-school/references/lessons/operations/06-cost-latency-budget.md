# 运营第六课：用成本与延迟预算约束运行

## 学习结果

学生能把质量、风险、成本和延迟放在同一上线决定中，并定义每任务预算、尾部延迟与停止条件。

## 核心概念

平均 token 和平均响应时间会掩盖长尾与重试。预算至少包含单任务资源、最大步骤/工具调用、P95/P99 延迟、人工复核时间和失败恢复成本。

## 决策框架

先定义用户等待与业务价值，再为质量和风险设不可交易的阻断项；对满足阻断项的方案比较全链路成本和尾部延迟。超预算时优先收缩上下文、步骤、工具或架构，不用降低安全门换速度。

## 来源

- `[CLM-006]` 与 `[SRC-GOOGLE-SRE-MONITORING]` 支持以可行动指标和环境结果观察运行。
- `[CLM-002]` 支持从最简单可评测架构开始。

## 讲授

五 Agent 客服方案的质量可能略高，却增加消息、上下文和尾部故障组合。比较时要计入模型、检索、工具、重试、评测、人工审查和事故成本。SRE 的 SLO 思想可帮助定义延迟目标，但课程不把服务 error budget 直接等同为 Agent 质量预算。

### 决策推演：成本不是一个数字

单任务成本至少分成稳定发生的基础成本、只在部分任务出现的分支成本、失败后的恢复成本和维持系统的固定成本。模型调用便宜，不代表工作便宜：一次低价尝试如果频繁触发人工复核、重试和事故调查，全链路成本会高于更简单的规则流程。预算卡应声明计量单位，例如“每个被业务接受的完成结果”，避免用每次调用掩盖未完成任务。

延迟同样要沿关键路径计算。并行调用可能降低中位时间，却让最慢依赖决定尾部；串行评审可能增加等待，却减少高影响返工。P95/P99 目标应与用户或下游截止时间对应，并把排队、人工审批和恢复纳入，而不只测模型响应。对异步工作，还要记录完成时限与超时升级，而不是把“用户不用等待页面”解释为没有延迟成本。

优化顺序应保留阻断门：先删除无价值步骤和重复上下文，再缓存稳定结果、并行独立只读动作、选择更合适的模型或降级路径。若必须取消安全控制才能满足预算，正确结论可能是任务不适合当前 Agent 方案，而不是继续上线。

## 失败模式与边界

- 只看 token 单价；
- 用平均延迟隐藏长尾；
- 为达预算取消权限控制或评测；
- 用模拟成本宣称真实 ROI。

## 实操

为客服主线制作预算卡：质量阻断项、每任务上限、最大步骤、P95 目标、人工时间、超限动作和回退方案。

## 完成证据

- `developing`：能区分单价与全链路成本；
- `capable`：能定义预算和超限动作；
- `strong`：能比较架构并保留质量/风险阻断项。

## 降级路径

只设计测量方案；没有本地数据时不填虚构数值。
