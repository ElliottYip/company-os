# Lab：Agent 安全桌面演练

## 学习结果

学生能识别从不可信内容到工具副作用的攻击链，执行止损、证据保全、恢复和改进。

## 核心概念

本 Lab 串联数据边界、提示注入、最小权限和事故响应。所有内容均为无害合成字符串。

## 决策框架

按输入、数据、动作、输出四个边界定位断点；先限制影响，再调查和恢复。

## 来源

- `[CLM-010]` 支持外部内容与分层控制。
- `[CLM-022]` 与 `[SRC-NIST-SP-800-61-R3]` 支持事故记录、响应和恢复。

## 讲授

情境分四轮：附件含越权指令；Agent 尝试调用发送工具；运行时拒绝但 trace 含敏感摘要；团队准备恢复。学生每轮更新信任边界卡和事故卡，区分“攻击未成功”与“系统没有治理问题”。

本练习故意让一层控制成功、另一层控制失败。运行时拒绝发送证明动作边界有效，却不能抵消模型把不可信内容当指令、最小权限设计不足或 trace 访问过宽。安全判断必须逐层记录“攻击走到哪里、哪层阻断、还有什么资产已暴露”，不能用最终没有外发概括整个系统。

运行 `node scripts/run-practice-lab.mjs --scenario agent-security --round 1`，一次只揭示当前轮。三轮结构练习完成后，导师追加恢复讨论：哪些凭据需要撤销、哪些证据必须保留、哪些日志需要收紧访问、什么回归门允许重新开放。不要让 Agent 自己总结后直接恢复它自己的权限。

## 失败模式与边界

- 只检查模型是否服从恶意文本；
- 忽略日志中的敏感信息；
- 运行时拦截一次就宣称完全安全。

## 实操

1. 用 `--template agent-security` 创建同一份事故提交；
2. 对每轮写动作、证据、禁止动作、负责人和恢复条件；
3. 用 `--score agent-security --submission <file>` 检查结构；
4. 导师复核是否把“策略拒绝”误写成“没有事故”，以及是否删除了调查所需证据；
5. 最终交付攻击链、输入/数据/动作/输出四层控制、立即动作、恢复门和剩余风险声明。

## 完成证据

- `developing`：能识别不可信输入；
- `capable`：机器结构分不低于 80，能布置分层控制并止损，且没有恢复或证据保全阻断错误；
- `strong`：能解释每层控制的独立价值，并兼顾可用性、恢复和剩余风险。
