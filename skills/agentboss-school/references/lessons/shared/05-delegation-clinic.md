# Lab：委派设计诊所

## 学习结果

学生能把一个模糊任务重构为有模式选择、控制边界、结果合同和架构回退的可管理工作。

## 核心概念

本 Lab 串联委派适配、工作拆分、结果合同与编排选择，不新增理论。

## 决策框架

依次完成一票否决、六段拆分、八项结果合同和最小架构；每次增加自治都必须有评测证据。

## 来源

- `[CLM-002]`、`[CLM-003]` 支持最小架构与结果接口。
- `[CLM-013]` 支持正确暂停和接管。

## 讲授

导师使用招聘筛选合成案例，先示范把“自动筛人”收缩成“整理证据、真人决定”。学生可换成抽象真实任务，但不得粘贴敏感材料。

诊所按四次收缩运行。第一次做一票否决：高影响决定、不可接受后果、缺少可靠验收或缺少合法数据时，先改成真人保留或 Agent 辅助。第二次沿“输入—分析—建议—决定—动作—验证”拆边界，指出真正产生副作用的阶段。第三次写结果合同，让上游证据、不确定性、禁止动作和暂停条件能被下游检查。第四次才选择规则、工作流、单 Agent 或多 Agent，并写出升级到更复杂架构所需的证据。

招聘案例的正确目标不是找到一个更聪明的筛选 Agent，而是暴露价值判断在哪里发生。Agent 可以从获准材料中提取与岗位标准相关的证据、标记缺失和生成比较表；它不能把代理变量偷偷写入评分，也不能在没有负责真人和申诉路径时自动拒绝候选人。即使模型精度看似足够，高影响决定的组织与法律边界仍需另行确认。

导师还应给一个过度保守反例：把所有步骤都留给真人，以至于 Agent 只负责改写句子。学生需要找出真正可验证、低副作用且能减少机械工作的部分。课程目标不是自治最大化或最小化，而是让控制方式与后果、证据和责任匹配。

## 失败模式与边界

- 直接选模型；
- 把高影响决定藏在下游动作；
- 多 Agent 代替工作拆分。

## 实操

交付委派适配卡、控制边界图、结果合同和架构决策记录，并做两次一致性检查：

1. 结果合同中的每项允许动作，是否在控制边界图中有执行者、证据和暂停点；
2. 架构决策中的每个 Agent，是否解决了规则或单一执行者无法解决的具体问题。

若四份工作件冲突，优先收紧动作与权限，再回到前一张卡修正，不用补一段 prompt 掩盖结构问题。

## 完成证据

- `developing`：能识别真人保留部分；
- `capable`：四份工作件逻辑一致，且高影响决定没有被藏进上游评分；
- `strong`：能同时识别过度自治与过度保守，定义复杂度升级证据和安全回退。
