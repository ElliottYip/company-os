# 治理第一课：审批准确动作，而不是相信 Agent

## 学习结果

学生能在高风险审批中核对完整动作绑定，识别内容、责任上下文或有效期变化，并作出批准、拒绝或要求重新提交的决定。

## 核心概念

1. “允许某类动作”不等于“允许任意一次动作”。
2. 审批必须绑定准确动作、输入摘要、工作、责任合同、执行 Agent、负责真人、证据/结果和有效期。
3. 绑定变化、过期、已决定、审批人不匹配时必须 fail closed；不能把旧批准复用于新动作。

## 决策框架

审批人先判断自己是否是正确责任人，再核对动作、输入、工作、Agent、证据与有效期是否与眼前内容一致；信息不足或任一绑定变化就要求新请求，业务风险不可接受则拒绝。

## 讲授

低质量审批只有一个按钮：“同意 Agent 发布吗？”它实际上让审批人批准一个模糊意图。内容可能在审批后变化，Agent 可能换了执行上下文，甚至使用了另一个数据版本。

精确审批批准的是一个不可偷换的对象：

```text
审批对象 = 动作身份与类型
         + 动作输入摘要
         + 所属工作
         + 当前责任合同
         + 执行 Agent
         + 负责真人
         + 支持证据与候选结果
         + 过期时间
```

其中输入摘要不是为了让真人读哈希，而是防止“审的是 A，执行的是 B”。界面仍应展示真人可理解的内容，但系统用摘要确认执行输入没有被替换。

审批人有三种合理决定：

- **批准**：对象明确、证据充分、风险在合同边界内；
- **拒绝**：业务上不应执行，或风险不可接受；
- **要求重新提交**：信息不足、内容已改、责任链变化或请求已过期。技术上这不是复用旧请求，而是生成新绑定。

很多系统把审批设计成“真人在环”的装饰。真正的真人负责意味着审批人必须是对应负责真人，决定被记录，执行动作与批准对象一致，而且一次批准不能跨动作复用。

## 失败模式与边界

- 审批页只显示“允许/拒绝”，没有人可理解的动作内容；
- 内容审批后仍可修改，执行时也不校验摘要；
- 高频审批造成习惯性点击，却没有抽样、演练或权限收缩；
- 精确审批降低偷换与复用风险，但不能保证审批人判断正确。

## 实操

情境：

> 市场简报发布请求显示：动作 `publish-content`；输入摘要 `sha256:demo-publish-action`；工作 `demo-work-001`；执行者 `demo-researcher`；负责人 `demo-boss`；有效期 08:10；计划和数据读取证据齐全。

先给示范答案：如果内容预览与摘要绑定一致、证据满足结果合同且当前时间未过期，负责真人可以批准。随后改变一个条件：发布内容在审批页打开后被编辑。正确动作是拒绝旧请求或让系统生成新请求，不能继续点批准。

可选巩固：再改变负责人或有效期，让学生指出为什么必须失败关闭。

## 完成证据

- `developing`：知道高风险动作必须暂停给真人。
- `capable`：能核对动作、输入、责任人、证据和有效期，并识别变化后重提。
- `strong`：能解释为什么旧批准不能复用于新输入或重复执行。
- 未观察到审批判断：记录 `unknown`。

## 降级路径

本课使用桌面情境即可。不要让学生为了练习连接真实发布、付款、身份或 shell 权限。
