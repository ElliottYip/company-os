# 治理第四课：给数据画出可执行边界

## 学习结果

学生能为 Agent 工作定义数据目的、类别、来源、允许处理、驻留、留存与删除边界，并在边界不清时收紧任务。

## 核心概念

数据“能访问”不等于“获准用于当前目的”。边界同时约束数据主体、敏感级别、用途、处理位置、下游接收方、保存时间和派生物。

## 决策框架

从业务目的倒推最小数据集；逐项标注来源与授权、敏感级别、允许处理、禁止用途、驻留/出境要求、留存和删除。无法确认的数据先排除，不用泛化同意替代具体边界。

## 来源

## 讲授

研究 Agent 为市场简报需要公开市场数据，不因此获得客户名单、员工记录或生产日志。即使这些数据能提高个性化，也必须另有目的与授权。边界还要覆盖输出：摘要、向量、缓存和 trace 仍可能保留敏感内容，不能因“不是原文”自动脱离治理。

一张可执行数据卡应让运行时能拒绝越界，而不只是写“遵守隐私”。例如只允许读取指定演示数据集、禁止外发与训练用途。处理区域与保留期限必须来自适用法律、合同和组织政策；课程不编造统一的“安全天数”。

### 决策推演：边界沿数据变形继续存在

原始文本经过分块、嵌入、摘要、分类或日志记录后，不会自动失去敏感性。向量可能支持成员推断，摘要可能保留个人事实，trace 可能保存完整工具参数。数据边界卡必须列出派生物、缓存、备份和观测副本，并为每类对象定义访问者、用途和删除路径。仅删除上传文件而保留索引与日志，不算完成删除。

目的限制要求能回答“为什么这项字段是完成当前结果所必需”。为了生成公开市场简报读取客户名单，即使技术上方便，也属于目的漂移。若同一数据未来要用于训练、评测或产品分析，应建立新的用途判断与授权，而不是沿用原工作同意。对无法确认来源或许可的数据，收紧任务范围通常比猜测合规状态更可靠。

跨服务处理还要记录接收方和位置。模型供应商、检索库、观测平台和人工审核界面都可能成为接收方；“数据没有离开我们的应用”不能在这些链路存在时成立。具体驻留、跨境、保留和通知义务必须由适用法律、合同与组织政策确定，本课只提供发现问题的控制面。

## 失败模式与边界

- 用“内部数据”作为唯一分类；
- 只管输入原文，不管缓存、向量和日志；
- 供应商可处理就推导为组织已授权；
- 本课不替代适用地区的法律与合规审查。

## 实操

为外部研究主线填写数据边界卡：目的、允许数据、禁止数据、处理位置、下游、留存、删除和越界动作。

## 完成证据

- `developing`：能区分技术访问与目的授权；
- `capable`：能写完整数据生命周期边界；
- `strong`：能覆盖派生物、日志和跨境/驻留限制。

## 降级路径

只使用合成字段，不收集个人或客户资料。
