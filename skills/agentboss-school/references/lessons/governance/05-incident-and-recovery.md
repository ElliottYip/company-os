# 治理第五课：响应 Agent 事故并恢复责任链

## 学习结果

学生能完成事故分级、止损、证据保全、影响判断、受控恢复和无责复盘，不让 Agent 自行掩盖或修复高影响事故。

## 核心概念

事故响应关注已经发生或可能发生的影响。最小顺序是：发现与分级 → 限制影响 → 保全证据 → 调查范围 → 恢复 → 沟通与复盘 → 跟踪改进。

## 决策框架

先按数据、权限、副作用和业务影响分级；撤销危险能力但保留必要证据；确定事故指挥、技术处置、业务责任与沟通责任；只有恢复条件被验证后才重新开放。

## 讲授

发现 Agent 可能外发资料时，第一目标不是让它生成解释，而是限制发送能力、保全动作与访问记录、确认影响对象。删除日志或立即重跑会破坏判断依据。恢复也不是“修好提示词就上线”，而要验证凭据轮换、权限收缩、受影响数据处置和回归测试。

无责复盘不等于无人负责。它避免把系统性缺陷缩成个人失误，同时明确谁负责每项改进、何时验证关闭。

### 决策推演：先分清事故与普通失败

模型输出质量下降可能进入评测与回归流程；越权数据访问、未授权外发、重复高影响动作或无法确认影响范围，则可能进入事故响应。区分点不在“有没有报错”，而在保密性、完整性、可用性、权限和业务后果是否受到实际或可信威胁。运行时成功阻断攻击仍可能暴露控制缺口，值得记录和修复，但分级应基于影响与剩余风险，不能为了显得安全把所有事件升成最高级。

止损动作也要保留调查能力。撤销发送权限不等于销毁执行记录；隔离工作不等于清空所有状态；轮换凭据后仍要确认旧凭据在哪些系统和缓存中出现。事故记录至少保留时间、来源、动作身份、审批绑定、工具结果、受影响对象和处置人，并按组织规则控制访问与完整性。

恢复分为技术恢复与业务恢复。技术组件重新可用后，还需核对副作用、通知责任方、重建授权并验证业务结果。回归测试应覆盖本次故障路径，而不是只跑正常样本。复盘产生的行动项必须有负责人、期限和验证方式；长期未关闭的关键行动应进入运营复盘并限制扩张。

## 失败模式与边界

- 先追责后止损；
- 让同一 Agent 调查并清理自己的事故；
- 恢复前不验证权限和数据状态；
- 复盘只有时间线，没有改进负责人。

## 实操

使用安全 tabletop：研究 Agent 尝试把内部摘要发送到未授权目标。填写事故卡：级别、立即动作、证据、可能影响、责任角色、恢复门和三项改进。

## 完成证据

- `developing`：能先止损并保全证据；
- `capable`：能设计分级、责任角色和恢复门；
- `strong`：能把复盘转成可验证改进闭环。

## 降级路径

只做合成演练；若是真实事件，停止课堂并进入组织事故流程。
