# 团队第五课：判断 Agent 是否创造净价值

## 学习结果

学生能用本地基线、业务结果、全成本、风险与替代方案作出继续、收紧、扩大或停止决定，不用 demo 或相关性报告证明 ROI。

## 核心概念

价值不是 token 节省，也不是任务变快。净价值比较业务结果变化与模型、工具、集成、评测、人工审查、异常恢复、培训和维护成本，并考虑风险与机会成本。

## 决策框架

先定义非 AI 基线和可归因观察窗口；选择结果、质量、真人时间、成本、延迟与风险指标；与受控替代方案比较；报告不确定性和未计成本。阻断风险不能由平均收益抵消。

## 来源

- `[CLM-015]` 与 `[SRC-DORA-AI-2025]` 只支持“组织条件可能放大采用结果”的待验证假设，不支持跨行业因果 ROI。
- `[CLM-007]`、`[CLM-008]` 支持本地评测、重复观察与限制披露。
- `[SRC-NIST-AI-RMF-1]` 支持同时考虑成本、收益、风险和非 AI 替代。

## 讲授

如果起草节省一小时，但复核、返工和事故待命增加两小时，速度指标会误导。先记录当前流程，再限定试点范围，比较同类任务。模拟数字只能演示算法，不能成为客户成效。结果不确定时，合理决定可以是继续收集证据，而不是强行宣布成功或失败。

### 决策推演：价值判断需要反事实与约束

没有基线，就不知道变化来自 Agent、任务难度、人员经验还是同期流程调整。基线不必完美实验，但要定义可比较任务、观察窗口和非 AI 替代方案，并记录样本选择差异。若只把最容易自动化的任务放进试点，再与全部历史任务比较，得到的提升不能归因于系统。

全成本要按业务接受的结果计量：模型、检索、工具、集成、评测、复核、失败恢复、值班、培训、维护和供应商切换都可能进入分母。与此同时，不能把所有风险随意货币化后用平均收益抵消。法律禁止、未授权高影响动作或明确安全阻断项应先决定“不能上线”，再在可接受方案之间比较净价值。

价值决定应预先写出四种路线：证据满足时扩大；质量可控但人工负担过高时优化或收紧；关键风险失败时停止；样本不足时继续受限取证。这样团队不会在看到结果后临时修改成功口径。课程只教本地测量设计，不从 DORA 或厂商报告推导某个组织的 ROI。

## 失败模式与边界

- 用供应商 benchmark 当本地价值；
- 只计 API 账单；
- 忽略选择偏差和任务变化；
- 把高影响风险折成一个随意金额后抵消。

## 实操

完成价值台账：基线、结果指标、全成本、风险阻断项、替代方案、证据限制和四种决策条件。

## 完成证据

- `developing`：能区分效率和净价值；
- `capable`：能建立基线与全成本；
- `strong`：能处理归因限制、替代方案和停止决定。
