# 团队第四课：把 Skill 变成可运营流程

## 学习结果

学生能把一次成功做法整理成有输入、输出、边界、证据、版本、评测和回退的 Skill，而不是保存一段神秘提示词。

## 核心概念

Skill 是供 Agent 执行的过程接口：路由说明保持精简，领域知识按需加载，脆弱步骤交给确定性脚本，工作结果由评测验证。一次好输出不是可复用流程。

## 决策框架

先固定工作结果与失败样本，再分离稳定规则、可变知识和确定性动作；定义输入边界、工具授权、产物、停止条件、版本兼容、回归集与回退。只有执行者确实需要的信息才进入上下文。

## 来源

- `[CLM-003]` 支持把结果、证据、边界和未完成状态变成可检查接口；具体 Skill 文件结构是 AgentBoss 项目选择。
- `[CLM-007]`、`[CLM-008]` 支持版本化评测与重复 trial。
- `[CLM-004]` 支持最小且可追溯的上下文。

## 讲授

把二十页操作手册塞进一个入口文件，会增加加载成本和冲突。入口只负责识别任务、选择流程和指出何时读取哪份 reference；固定校验、索引和签名使用脚本；课程知识与案例分开。发布新版本前，在冻结任务集上回归并记录不兼容变化。

### 决策推演：Skill 是可演进的过程合同

入口描述解决“什么时候调用、边界是什么”，reference 解决“执行到当前阶段需要知道什么”，脚本解决“哪些动作必须确定性和可重复”。这三层分开后，知识更新不必改动执行器，校验升级也不必把整份手册加载进模型。重复规则只保留一个权威位置，其他文件用引用连接，避免不同版本给出冲突答案。

把一次好对话固化为 Skill 之前，要先收集正常、边界、拒绝和失败样本，并写出不完成状态。版本升级需要说明输入/输出是否兼容、存档如何迁移、旧产物能否验证、出现回归怎样退回。回归集必须冻结一部分未参与调优的任务，且保留环境与依赖版本；否则“新版本更好”可能只是对已见样本的适配。

Skill 仍然不能越过组织权限。它可以描述需要某工具，却不能因被安装就获得连接器、生产数据或发布权。运行时授权、精确审批和结果验收继续独立存在，这正是把过程复用与权力授予分开的价值。

## 失败模式与边界

- 把聊天历史直接命名为 Skill；
- 同一规则在入口、课程和案例重复三份；
- 没有版本、失败状态或回退；
- 用 prompt 自评替代环境结果。

## 实操

把一个团队流程画成 Skill 契约：触发、输入、按需资料、工具、输出、证据、禁止动作、版本和回退。

## 完成证据

- `developing`：能区分入口、知识与脚本；
- `capable`：能写边界、证据和回归；
- `strong`：能设计兼容升级和安全回退。

## 降级路径

只设计目录与契约，不安装或执行外部 Skill。
