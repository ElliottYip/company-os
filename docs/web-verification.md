# Web verification

## Agent Boss deterministic vertical

The Company OS-owned Web exposes four projections over the same deterministic
application state: Office, Work and Approvals, Responsibility, and Connectors.
The customer shell does not import or embed competitor pages. Stable section and
event codes are independent of display copy.

`CompanyOSApplicationClient` is the Web anti-corruption boundary. The default
composition is the deterministic Demo client. The formal client now consumes
only `GET /api/v1/companies/{companyId}/agent-boss`, maps stable projection
codes into the shell, and exposes no Demo mutation. The same client works for
managed-cloud and self-hosted profiles without exposing persisted events or
competitor DTOs. The Raft host contract still contains only a mount element,
base path, and navigation callback.

The verified browser flow is:

1. Assign the fixture work.
2. Record the deterministic plan.
3. Record simulated tool activity and evidence.
4. Pause on the exact high-risk action.
5. Let the accountable fixture human approve or reject.
6. Project the initiator, accountable human, executing fixture Agent,
   permissions, data authorization, approval, evidence, and result.
7. Reset only fixture state.

The connector projection reports zero model calls, enterprise data reads, and
external network requests. State-machine and journal implementations are named
as fixtures; formal connectors remain visibly unbound.
