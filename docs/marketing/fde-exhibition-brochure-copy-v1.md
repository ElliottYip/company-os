## P2—P3 跨页：未来与证据

### P2 左页｜未来正在发生

# AI 已经可以自己干活

过去，我们手动完成工作每一步。

现在，Agent 可以读资料、查数据、调用工具、完成一连串任务。碰到需要审核的事，再交给人判断。

公司的工作方式也会跟着变：

- 重复工作交给 Agent；
- 人负责目标、判断和审核；
- 一个负责人可以带多个 Agent；
- 公司积累的不只是文件，还有能反复使用的流程和 Skill。

- Microsoft 在 2025 年提出 Agent Boss：员工将开始构建、分配和管理 Agent。
- OpenAI 把 Agent 定义为能够代表用户完成工作流的系统，不只是聊天机器人。
- Google 认为企业 Agent 要连接公司的数据、工具、记忆和运行环境，才能真正工作。
- Anthropic 发现，人在实际协作中更多决定“做什么”，Agent 更多负责“怎么做”。

**公司的运作效率，会随着AI Native程度拉开差距。**

### P3 右页｜这些数字已经发生

- Microsoft 2025 Work Trend Index 调查了 31 个国家的 31,000 名员工。81% 的受访领导者预计，未来 12—18 个月 Agent 会进入公司的 AI 战略。
- OpenAI 2025 年公布，已有超过 100 万家企业客户在使用其产品。
- OpenAI 2026 年的企业使用数据中，自 2 月以来，Codex 周活跃用户在法务部门增长 108 倍，在销售和招聘部门均增长 41 倍，在市场部门增长 26 倍。

### 已经进入生产的公开案例

- **Cisco**：OpenAI 公布的客户资料显示，Codex 帮助其把代码评审时间缩短 50%，部分项目从数周缩短到数天。
- **Carlyle**：其多 Agent 尽调系统的开发时间减少超过 50%，Agent 准确率提高 30%。
- **TELUS**：Google Cloud 客户案例称，其 AI 系统每年节省 5,390 万美元，客户问题解决速度提高 87%，30% 的来电由 AI 主动解决。
- **Lowe’s**：OpenAI 客户资料显示，Lowe’s 已在 1,700 多家门店为员工提供 AI 项目指导工具。

## P4 企业现在最常见的状态

# 想要升级提效，但不知道从哪里入手

很多企业已经试过 AI：

- 买过会员，员工偶尔问几个问题；
- 做过 Demo，演示时很好，上线后没人用；
- 看了很多案例，回到自己公司却套不上；
- 每个部门都说有需求，但排不出先后；
- 想建知识库，资料却散在微信、Excel、PDF、网盘和员工电脑里；
- 担心数据安全，也不知道 Agent 能开放多大权限。

### P4 下半页｜为什么自己做容易卡住

# AI 升级横跨了四件事

```text
老板想要的结果
        ↓
一线员工的工作流程
        ↓
数据和系统在哪里
        ↓
技术怎么做出来
```

少一层，项目就容易停住。

### 只听老板

方向很大，但找不到具体从哪项工作开始。

### 只听一线

会得到很多零散需求，却不知道哪个最值得投入。

### 只找软件公司

对方需要清楚的需求文档，但企业现在最缺的就是清楚的需求。

### 直接买标准产品

上线很快，但公司的流程不一定适合它。

### 一开始就建大平台

钱和时间先花出去了，业务价值还没有验证。

企业需要一个人把业务、产品和技术接在一起。这就是 FDE 的工作。

## P5 What is FDE

# FDE 从模糊问题开始，做到结果出来

Forward Deployed Engineer 不是坐在客户办公室写代码的人。

FDE 先去现场看真实工作：老板为什么想做 AI，一线每天怎么操作，数据放在哪里，哪些地方最耗时间、最容易错、最影响客户。

问题看清后，再决定怎么做：

- 现成软件能解决，就直接用现成软件；
- 一个 Skill 能解决，就不做大系统；
- 需要连接原有系统，就做集成；
- 需要整理数据，就先建数据库或知识库；
- 一条流程适合 Agent，就把人和 Agent 的分工设计清楚。

## P6 我们能做什么

# 从一个小工具，到一次公司级 AI 升级

### 一个具体问题

- 企业专属 Skill
- 文档、表格和图片处理
- 报价、录单、对账、报告自动化
- 小型定制 SaaS

适合：问题明确，希望尽快看到效果。

### 一条业务流程

- 访谈和流程整理
- 多角色 Agent
- ERP、CRM、飞书、钉钉、企微等系统连接
- 异常处理和人工确认
- 进度、结果和操作记录

适合：工作跨多人、跨系统，靠人工反复传递。

### 一套数据基础

- 业务数据库
- 企业知识库
- 数据整理和统一命名
- 权限和使用范围
- 为 Agent 提供可信的数据

适合：资料很多，但找不到、用不准、无法共享。

### 一次公司级升级

- 找出各部门适合 AI 的工作
- 重新设计人和 Agent 的分工
- 建立权限、审批和责任记录
- 制定试点顺序和后续计划
- 培训企业自己的 Agent Boss

适合：老板希望系统推进，不想让各部门各自尝试。

## P7 我们怎么开始

# 先做一次诊断，再决定要不要开发

### 1.

先确认企业为什么要做 AI：省时间、少出错、增加收入，还是改善整个公司的工作方式。

### 2.

我们会看员工实际使用的表格、文件、聊天工具和业务系统，也会看正常流程之外的各种例外。

### 3.

按价值、难度、数据条件、风险和验证时间排序。不是所有问题都要用 AI。

### 4.

只选一项工作，先约定负责人、数据、范围和判断结果的指标，再做出能用的版本。

### 5.

真实用户用过以后，再决定继续修改、推广到其他部门，还是停止。

## P8 一次试点会交付什么

# 不交一个演示，交一套能验证的东西

根据项目范围，试点通常包括：

- 原来的工作流程图；
- 找到的问题和改造范围；
- 可以运行的原型或系统；
- 使用的数据和权限说明；
- 人和 Agent 各自负责什么；
- 哪些动作需要人工确认；
- 上线前后的对比方法；
- 继续做、调整或停止的建议。

我们会提前写清楚：

- 谁负责；
- 做到哪里算完成；
- 什么不在这次范围内；
- 怎么判断有没有效果。

## P10 后续服务：Agent Boss 培训

# 系统上线了，还要有人会带 Agent 工作

FDE 负责把企业 AI 升级做出来。

系统上线后，企业自己的管理者和员工要学会：

- 给 Agent 说清目标和完成标准；
- 判断哪些工作可以交出去；
- 检查 Agent 的过程和结果；
- 处理异常、退回修改或暂停任务；
- 管好数据、工具和权限；
- 把好用的方法做成团队共同使用的 Skill；
- 对最后的业务结果负责。

我们把这套培训叫做 **Agent Boss**。

它不是一门提示词课，也不是教员工多用几个 AI 工具。它教企业的人怎么管理一支由人和 Agent 组成的团队。

### 服务关系

```text
FDE：把系统做出来
Agent Boss：教团队接过去，继续用、继续改
```

# 展台短文案

## 10 秒介绍

我们帮企业做 AI 升级。先去现场找到最值得改的一项工作，再做成 Skill、定制 SaaS、数据库或 Agent 流程。

## 30 秒介绍

很多老板知道公司要做 AI，但不知道先从哪里开始。我们先看老板想解决什么，再去看一线每天怎么工作，找出最值得改的一项。问题看清后，我们会选择合适的做法：可能只是一个 Skill，也可能是定制 SaaS、数据库或完整的 Agent 流程。先做一个小试点，看到结果以后再决定要不要扩大。

3. **别急着买 AI，先找出最值得改的一项工作。**
